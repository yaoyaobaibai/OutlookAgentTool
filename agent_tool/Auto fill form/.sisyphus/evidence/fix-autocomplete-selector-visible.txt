FIX: Autocomplete selector targets visible dropdown div instead of hidden input
===============================================================================
Date: 2026-08-03
Workflow: GR-Acubuy Create Goods Receipt (workflows/gracubuy_gr_flow/workflow.json)

BUG (observed in real browser run)
----------------------------------
Running the workflow failed on the Order field:
  Autocomplete failed for '#body_x_tabc_prxDelivery_prxprxDelivery_x_selOrder':
  Locator.wait_for: Timeout 5000ms exceeded.
  locator resolved to hidden <input type="hidden" value="139221" ...
    class="selector-hidden-field" id="..._x_selOrder">

Root cause: workflow.json Order (and Approver 2) fields set `selector` to the
iValua HIDDEN input (`type="hidden"`, `class="selector-hidden-field"`).
AutoCompleteHandler.execute() does self.page.locator(selector).wait_for(state="visible")
-- a hidden element is NEVER visible -> 5s timeout -> 2 retries -> fail.
The real visible, clickable element is the wrapping dropdown div which carries
the hidden input's id in its data-selector attribute.

PART 1 - workflow.json selector changes
---------------------------------------
- Order:      "#body_x_tabc_prxDelivery_prxprxDelivery_x_selOrder"
            -> "div[data-selector='body_x_tabc_prxDelivery_prxprxDelivery_x_selOrder']"
- Approver 2: "#body_x_tabc_prxDelivery_prxprxDelivery_x_selector_single_delivery_20240816105603081"
            -> "div[data-selector='body_x_tabc_prxDelivery_prxprxDelivery_x_selector_single_delivery_20240816105603081']"
- All other field config preserved verbatim (type/required/handler_config with
  mode, search_selector, result_selector, wait_after_input_ms, clear_before).
- Stage navigation wait on the _search input unchanged.

PART 2 - autocomplete_handler.py (minimal change)
-------------------------------------------------
handlers/autocomplete_handler.py, _find_search_input(): after
search_input.wait_for(state="visible", timeout=5000), add ONE line:
    search_input.click()
This mirrors the recorded interaction (click the _search field, then type),
guaranteeing the control is focused before filling. It only runs when the
search input exists (function already returns None otherwise), so it is guarded
naturally. No other handler logic changed; search_selector/result_selector/
wait_after_input_ms handling untouched.
