Fix: Tkinter lambda closure bug (Python 3.14 exception-variable semantics)
=======================================================================
File:       form_filler.py
Date:       2026-08-03
Interpreter: C:\Users\p1325970\AppData\Local\Python\bin\python.exe

BUG
---
In `_run_engine_thread`, the `except Exception as e:` block scheduled a
deferred lambda that referenced the exception variable `e`:

    self.root.after(0, lambda: self._on_execution_error(e))

`self.root.after(0, ...)` runs the lambda on the Tk main thread's NEXT event
loop iteration, i.e. AFTER the `except` block has exited. Python 3.14
deletes the exception variable at the end of the `except` block (it is
treated as an unbound free variable), raising:

    NameError: cannot access free variable 'e' where it is not associated
    with a value in enclosing scope

FIX
---
Bound the exception as a lambda DEFAULT argument (captured at definition
time), so the deferred lambda does not rely on the outer `e`:

    self.root.after(0, lambda err=e: self._on_execution_error(err))
